## 2. 产品背景

设计师长期积累的网页、截图、作品、方法、甲方反馈和决策过程散落在浏览器收藏、Eagle、Pinterest、Figma、Notion、聊天记录、本地文件夹和个人记忆中。传统工具擅长“保存东西”，却没有把以下链路连成闭环：

```text
日常收藏并记录原因
→ 在真实项目里按设计意图找回
→ 拆解甲方语言与判断缺口
→ 用历史素材、方法和经验形成证据
→ 记录选择、放弃和权衡
→ 用结果修正个人认知
→ 在下一项目再次调用
```

设计师真正流失的不只是图片，而是当时为什么关注、为什么选择、什么被否决、什么只对特定客户有效。DesignWan 要把视觉素材与判断历史转化为可追溯、可纠正、可持续调用的个人设计认知资产。

## 3. 产品愿景

成为设计师启动真实项目时的个人认知工作台：系统越来越理解用户的材料、方法和判断边界，但始终由设计师作最终判断。

长期价值不是“替用户设计”，而是：

1. 让灵感不丢失且能在项目中复用。
2. 让过去项目的成功、失败和权衡不白费。
3. 让设计认知能够被记录、召回、挑战、验证和修正。

## 4. 产品定位

### 4.1 一句话定位

一个持续学习设计师本人，将灵感素材、甲方需求、历史作品、项目经验和设计判断沉淀为长期个人能力的设计认知工作台。

### 4.2 不是什么

- 不是自动生成设计稿的 AI 设计工具。
- 不是替设计师打分或宣布唯一最佳方案的 AI 评委。
- 不是只存图片、标签和文件夹的素材库。
- 不是只整理会议纪要的需求分析聊天机器人。
- 不是把全局蜘蛛网当主界面的知识图谱展示器。
- 不是能静默建立不可见人格档案的推荐系统。

### 4.3 差异化

| 对比对象 | 对方主要价值 | DesignWan 的差异 |
|---|---|---|
| Eagle / 文件夹 | 保存、分类、查看 | 保存收藏意图、项目影响、决策与认知演化 |
| Pinterest / Behance | 发现和收藏公开案例 | 连接私人项目、客户语义、历史反馈和个人记忆 |
| Notion / Obsidian | 手工记录知识 | 视觉采集、混合检索、结构化需求和证据化决策 |
| Figma / FigJam | 项目内创作和整理 | 跨项目召回、来源管理、失败记忆和长期认知 |
| 通用 AI 对话 | 单次生成和总结 | 有作用域、有来源、可删除、可挑战的长期连续性 |

## 5. 产品原则

1. **设计师最终判断**：AI 提供结构、证据和挑战，不自动选择“最佳方案”。
2. **事实与推断分离**：原文、客户观点、用户判断、AI 推断、假设和已验证结论必须显式标注。
3. **低摩擦采集**：收藏入口不强迫填写大量字段；分析与整理异步完成。
4. **证据优先**：每条需求解释、召回、记忆和决策说明尽量绑定真实来源。
5. **记忆透明可控**：重要长期推断只能成为候选；用户可查看、确认、修改、限制、废弃和彻底删除。
6. **防止回音壁**：系统不仅学习偏好，还应展示反证、边界和邻近风格。
7. **默认最小作用域**：客户、私密项目和禁止学习内容不得越界召回。
8. **图谱服务任务**：底层完整建模，前端只展示当前判断需要的局部关系。
9. **MVP 是完整纵向闭环**：在新项目召回旧记忆之前，不用横向功能数量粉饰完成度。
10. **版权不做伪承诺**：记录来源和许可声明不等于系统作出可商用法律结论。

## 6. 目标用户

### 6.1 首要用户

长期目标用户是有真实项目经验、需要跨项目复用素材与判断的个人设计师，包括品牌、平面、网页视觉、包装、电商视觉、UI、UX、产品和交互设计师，以及自由设计师、小型工作室主理人。

首批封测主领域已锁定为品牌/网页视觉设计师，重点招募经常处理模糊甲方语言、同时有历史素材积累和真实项目复盘需求的用户；UI/UX 仅使用领域模板验证通用主通道，不参与首批 50/50 平均招募。

### 6.2 领域差异

| 领域 | 核心对象 | 主要判断维度 | 常用证据 |
|---|---|---|---|
| 品牌/视觉 | 品牌气质、构图、字体、色彩、材质、文化表达 | 识别、差异、传播、可信、价格感 | 海报、品牌案例、摄影、包装、历史提案 |
| UI/UX/产品 | 任务、信息架构、组件、流程、状态、业务规则 | 效率、可用性、完整性、认知成本、业务约束 | 页面、流程图、组件、可用性反馈、数据结果 |

采用 `通用设计认知主通道 + design_domain 领域模型/模板/词典/方法包`，不开发两套互不相干的产品。

## 7. 用户角色

| 角色 | MVP 权限 | 后续扩展 |
|---|---|---|
| Workspace Owner | 管理个人工作空间、素材、项目、记忆、隐私、导出和删除 | 可管理团队成员与规则 |
| AI Assistant | 在授权作用域内分析、召回、起草；无最终决策权和长期记忆直写权 | 可按策略调用更多工具 |
| Client / Stakeholder | MVP 仅作为项目数据对象，不登录系统 | 客户门户、受控评论/查看 |
| Team Member | MVP 不提供 | 团队素材、团队知识、角色权限 |
| System Operator | 仅访问控制面的账号、订阅、模型目录和 Managed 用量元数据；无法通过控制面读取本地业务内容 | 受审计的控制面支持和合规操作 |

从第一天预留 `workspace_id`、`owner_type`、`owner_id`、`visibility`、`memory_scope`、`project_scope`、`client_scope`、`created_by`，但 MVP 产品界面只服务个人 Owner。

## 8. 用户痛点

1. 收藏时按来源保存，项目时却按意图和判断寻找，导致“存了但找不到”。
2. 收藏只保留整图和标签，局部价值、收藏原因和适用边界丢失。
3. “高级、年轻、科技感”等甲方表达无法直接转为可执行判断标准。
4. 历史项目的采用、否决、返工、反馈和结果没有回写，经验反复流失。
5. 通用 AI 缺乏可信的个人连续性，也容易把推断说成事实。
6. 只按旧偏好推荐会制造审美回音壁，用户越来越像自己的复印机。
7. 客户资料、未发布作品和个人认知高度敏感，越界召回会直接摧毁信任。
8. 来源失效、授权不明和外部分享时的版权风险缺乏系统提醒。

## 9. 核心使用场景

| 场景 | 用户任务 | 成功结果 |
|---|---|---|
| 日常浏览 | 快速保存网页、视口、全页、局部或单图并记录原因 | 素材带来源进入 Inbox，后台可继续分析 |
| 素材整理 | 补充上下文、裁切 Fragment、确认描述、关联项目/板 | 素材可按设计意图和局部价值召回 |
| 项目启动 | 创建客户/项目并导入甲方资料 | 原文保留，需求被分层拆解 |
| 判断建立 | 确认模糊词、冲突、追问、判断维度和标准 | 不再拿空洞形容词直接开工 |
| 方向探索 | 召回个人素材、历史经验和反向案例 | 形成正向、反向、边界证据板 |
| 决策沟通 | 创建设计命题，记录依据、风险、代价和选择 | 决策可追溯并可生成不同受众说明 |
| 项目收尾 | 记录反馈、结果并确认复盘草稿 | 可迁移经验与项目限定结论被区分 |
| 新项目 | 调用已确认记忆和个人词典 | 历史经验被复用但不越过作用域 |

## 10. 产品信息架构

```text
浏览器插件
├─ 页面/视口/全页/局部/单图采集
└─ 本地交接队列与处理状态

桌面主产品
├─ Home / Onboarding
├─ Inbox
├─ Library
│  ├─ Asset 详情
│  ├─ Fragment / Visual Feature
│  └─ 来源、版权与使用生命周期
├─ Projects
│  └─ Project Workspace
│     ├─ Brief / 需求拆解
│     ├─ Criteria / 判断维度
│     ├─ Evidence Board / 正反边界案例
│     ├─ Proposition / 设计命题
│     ├─ Decision / 决策与解释
│     └─ Review / 项目复盘
├─ Memory
│  ├─ 记忆候选与冲突
│  ├─ Personal Dictionary
│  └─ Path Dependency / 反向记忆
└─ Settings
   ├─ 本地数据位置、备份与删除
   ├─ 项目云 AI 授权与三类模型路由
   ├─ 可选账号、订阅与 Managed Cloud AI 用量
   └─ 隔离、提醒与个性化控制
```

Knowledge Graph 不作为默认一级“蜘蛛网”入口；关系在需求、证据、决策、素材和记忆详情中以局部关系图或时间线出现。

## 11. 核心用户流程

MVP 首要验收链路：

```text
插件收藏网页/截图/局部
→ 交给桌面端并在本地保存来源与收藏原因
→ 本地后台完成去重与索引；AI 按本地/逐项目授权云路由运行
→ 素材进入本地个人库
→ 创建客户与项目
→ 导入并拆解甲方需求
→ 用户确认模糊词、冲突和判断维度
→ 系统在合法作用域内召回素材与记忆
→ 用户组织正向/反向/边界案例
→ 创建设计命题并记录最终决策
→ 项目完成后生成复盘草稿
→ 用户确认记忆候选
→ 新项目再次召回该记忆
```

18 条独立用户流和对应业务流见 [MVP 用户与业务流程](MVP_USER_FLOWS.md)。

## 13. 各功能模块详细需求

本章定义跨模块体验；专项能力在第 14–23 章展开。

### 13.1 首次注册与冷启动

| 项目 | 需求 |
|---|---|
| 功能目标 | 让新用户理解隐私和核心闭环，并在没有历史数据时尽快获得可召回素材 |
| 使用者 | 首次使用的个人设计师 |
| 触发条件 | 首次启动桌面端并创建本地 Workspace |
| 前置条件 | 初始化本地数据库与业务文件目录；本地模式不要求登录，使用订阅或 Managed Cloud AI 时才需要可选账号 |
| 主流程 | 选择本地数据/应用管理备份位置 → 选择设计领域 → 查看本地数据和逐项目云 AI 默认值 → 可选登录控制面账号 → 选择安装插件、导入历史资料或使用示例 → 查看候选分类/记忆 → 进入 Inbox |
| 异常流程 | 可跳过导入；部分文件失败单项重试；不支持格式保留错误清单 |
| 业务规则 | 冷启动推断均为候选；不得直接形成已确认长期偏好；原始资料保留导入批次；每批最多 500 个文件，每个 Workspace 同时仅允许 1 个活跃批次和 1 个排队批次，按 UTC 自然日最多接收 2,000 个文件 |
| 数据要求 | 本地 Workspace、领域、隐私与 AI 路由设置、导入批次、来源映射、候选分类/记忆；业务正文、素材与记忆不写控制面 |
| AI 参与方式 | 初始分类、描述、重复检测、候选词典和记忆提取 |
| 用户控制 | 跳过、删除批次、逐项确认/拒绝候选、保持完全离线、为单个项目授权 BYOK/Managed Cloud AI |
| 验收标准 | 不登录、离线状态下可完成引导和核心本地流程；支持本地文件夹/作品集/历史文档的基础批量导入；推断不越过 `pending`；第 3 个并发批次被明确拒绝，第 501 个单批文件和 UTC 单日第 2,001 个文件不进入处理队列 |
| MVP | 是；Eagle/Pinterest/Notion 专用连接器可后置，但通用文件、书签/链接清单和 Figma 导出图片导入须可用 |

### 13.2 素材搜索与项目召回

| 项目 | 需求 |
|---|---|
| 功能目标 | 按关键词、视觉语义、设计意图、局部和历史使用找回素材与经验 |
| 使用者 | 素材整理和项目探索中的设计师 |
| 触发条件 | 用户搜索或确认判断维度后请求召回 |
| 前置条件 | 已有允许访问的 Asset/Fragment/Memory；至少关键词索引可用 |
| 主流程 | 输入查询/选择判断维度 → 作用域过滤 → 关键词+向量混合检索 → 重排 → 展示命中理由 → 用户加入项目/标记不相关 |
| 异常流程 | 向量失败降级关键词；无结果建议改写、扩大到个人通用范围或手动选择；不得自动跨客户扩大 |
| 业务规则 | 权限过滤先于向量/图谱扩展；每个结果提供 `why_recalled`；不相关反馈不直接写成长期偏好 |
| 数据要求 | 查询、过滤器、候选集、分数分解、命中理由、用户反馈、使用历史 |
| AI 参与方式 | 查询理解、混合召回、重排、理由生成；理由必须基于真实命中信号 |
| 用户控制 | 筛选作用域、排除风格、切换检索模式、标记不相关、固定/移除结果 |
| 验收标准 | 私密/跨客户越界为 0；向量不可用时仍能搜索；结果可追溯到召回信号 |
| MVP | 是；关键词、自然语言、向量、设计意图、反向案例和历史项目/反馈检索纳入 MVP，视觉相似和局部图像检索至少提供基础能力 |

### 13.3 证据板、设计命题、决策与解释

| 项目 | 需求 |
|---|---|
| 功能目标 | 把素材和经验转化为可比较的证据，把选择与代价记录为可复用决策 |
| 使用者 | 项目中的设计师 |
| 触发条件 | 判断维度已确认且已有召回/手工证据 |
| 前置条件 | 项目可编辑；至少一个判断维度 |
| 主流程 | 将素材/记忆分入正向、反向、边界 → 写参考点 → 创建命题 → 绑定支持/反证/假设/风险 → 用户选择、拒绝或搁置 → 记录 Trade-off → 保存决策 → 按受众生成说明 |
| 异常流程 | 无证据仍可建草稿但不得标为最终；引用被删显示占位；AI 解释缺证据时标记待验证或拒绝生成 |
| 业务规则 | AI 不自动选择；最终决策需用户保存；决策版本绑定需求分析版本；说明不得补写不存在的理由 |
| 数据要求 | BoardItem、Evidence、Proposition、Alternative、Tradeoff、Decision、Explanation、版本和引用 |
| AI 参与方式 | 起草命题、发现反证、生成面向客户/管理者/开发/团队/作品集/复盘的说明 |
| 用户控制 | 编辑全部文本、调整证据类别、拒绝 AI 草稿、锁定版本、撤销决定 |

### 15.2 素材价值生命周期

展示事实指标：再次打开、进入板、关联项目、参与判断、影响方向/最终作品、形成认知、长期未用和高度重复；不得输出伪科学的单一审美分。

### 15.3 来源与版权

- 尽力保存原始作者、网站、作品名、品牌、发布日期、平台、许可类型、是否可商用、是否仅供参考、是否用户原创。
- 支持来源补录、失效提醒、来源不明标记、导出版权提醒；外部分享默认隐藏受限素材。
- 系统只记录证据和用户声明，不作版权法律结论。

| 主流程 | 检测信号 → 生成低/中/高强度提醒 → 展示重复证据 → 推荐反向案例/邻近风格/未尝试方法 → 用户采纳、忽略或关闭 → 记录反馈但不自动改写偏好 |
| 异常流程 | 样本不足不下结论；项目硬约束导致重复时不误判为惯性；用户关闭后停止主动提醒 |
| 业务规则 | 提醒必须说明依据和不确定性；挑战不是随机噪声；不得把“不同”包装成“更好”；忽略不直接等于长期拒绝 |
| 数据要求 | PathSignal、证据窗口、阈值版本、提醒、推荐、用户反馈、提醒强度 |
| AI 参与方式 | 模式检测、反例/邻近案例检索、挑战理由生成 |
| 用户控制 | 提醒强度、暂停/关闭、选择领域/项目范围、反馈不相关 |
| 验收标准 | 系统能对有充分证据的重复路径给出来源、反例和可关闭提醒；无足够证据时不贴“审美固化”标签 |
| MVP | 基础版是；至少支持反向案例、同质收藏提醒和提醒强度设置，高级成长轨迹与复杂探索策略后置 |

## 23. AI 质量体系详细需求

| 项目 | 需求 |
|---|---|
| 功能目标 | 让需求拆解、召回、记忆和解释可评估、可回归、可追溯并能安全降级 |
| 使用者 | 产品、AI/数据、测试、研发；间接受益者为终端用户 |
| 触发条件 | 每次模型、Prompt、检索、记忆策略升级；线上关键 AI 调用 |
| 前置条件 | 固定数据集、Schema、版本、追踪与人工标注规范存在 |
| 主流程 | 运行离线 Evals → 检查质量/安全/成本阈值 → 灰度 → 记录线上采纳/拒绝/纠正 → 收集错误样本 → 回归并决定发布/回滚 |
| 异常流程 | Eval 不通过阻断升级；模型不可用走降级；Schema 非法拒绝写主表；追踪缺失视为失败而非“先上线” |
| 业务规则 | 所有 AI 输出结构化；Prompt/模型/Schema/原始输出版本仅存本地业务库；AI 不直写长期记忆；评测集隔离敏感数据并版本化；控制面不得持久化原始 Prompt 或业务正文 |
| 数据要求 | 本地 EvalDataset、Case、Expected、Grader、HumanScore、AIRun、PromptVersion、ModelVersion、Cost、Latency、UserFeedback；Managed Cloud 仅上报不含业务内容的计费用量 |
| AI 参与方式 | 被评估对象，也可用受控模型做辅助评分；关键安全项必须规则/人工复核 |
| 用户控制 | 查看 AI 标识、来源和不确定性；采纳/拒绝/纠正；逐项目选择 Local/BYOK/Managed 路由；云调用前查看最小必要上下文说明并授权 |
| 验收标准 | 至少覆盖需求完整度、事实/推断、模糊词、冲突、召回相关性、反例、记忆越界/冲突、过度泛化、解释依据、来源真实性、幻觉和旧偏好强化；升级前可重复回归 |
| MVP | 是；基础评测集、版本追踪、成本记录、采纳/拒绝记录和发布门禁属于 MVP |

### 23.1 首批质量门槛

- 严重隔离越界、删除后召回、把 AI 推断标成事实：零容忍。
- Schema 校验失败：不得写入业务主表。
- 需求拆解与解释：关键结论必须有来源或明确“无直接证据”。
- 召回：除相关性外，单独评测作用域正确率、反向案例质量和命中理由真实性。
- 记忆：单独评测自动写入越权、冲突漏检、适用范围过度泛化。

### 23.2 模型路由、选择与成本边界

- 所有文本、视觉、Embedding、Rerank 等 AI 能力通过统一能力接口调用，但路由必须分为三类，不能把权限与成本揉成一个“选模型”下拉框：
  1. `local_model`：通过本地模型 Adapter 在设备上运行，业务上下文不离开设备。
  2. `byok_cloud`：桌面端使用用户自己的 Provider 凭证直接调用；凭证存入操作系统安全存储，不进入 Supabase，Provider 留存和费用由用户与 Provider 的合同决定。
  3. `managed_cloud`：通过产品托管路由调用；只允许瞬时转发项目已授权的最小必要上下文，控制面仅记录不含业务内容的用量和计费元数据。
- 产品只展示通过对应任务能力、质量、安全、隐私和结构化输出评测的模型白名单，不承诺把 Provider 目录中的所有模型无条件开放。
- 用户可设置默认路由/模型，也可在具体任务前切换；所有云路由必须逐项目显式授权，并说明 Provider、数据类型、最小必要上下文、可能留存边界和撤销方式。
- 用户选择不能绕过任务能力、项目授权、内容最小化和 Provider 规则。Managed Cloud 还必须满足月度预算与限流；本地模型和 BYOK 不消耗 Managed Cloud 配额。
- Beta Managed Cloud AI 成本按用户、按月统计：15 美元为软阈值，达到后明确提示并降级高成本任务；20 美元为硬上限，达到后暂停 Managed Cloud 高成本 AI，保留本地、BYOK、手工编辑和基础索引能力。
- 模型切换、自动降级和暂停必须记录原因、实际路由、实际模型、成本与用户可见状态；不得用无提示的低质替换伪装成功。

## 24. 权限与隐私

### 24.1 MVP 控制项

```text
visibility: personal | project_private
memory_usage: allow | do_not_learn
cross_project_recall: allow_personal | allow_same_client | current_project_only
ai_route: local_model | byok_cloud | managed_cloud | manual_only
cloud_ai_project_grant: denied | granted
web_search: allow | disabled
share_restricted_assets: hidden | explicit_select
```

### 24.2 规则

- 业务数据本地存储、云模型处理和全网搜索是三种不同边界，不能揉成一个含糊的“隐私模式”；本地事实源不等于云 AI 永久禁用，云 AI 授权也不等于允许上传整个项目。
- 私密项目默认不进入跨项目召回；`do_not_learn` 内容不得生成个人长期记忆。
- 本地模式可离线完成存储、整理、项目、记忆、关键词/本地索引与已安装本地模型能力；没有本地模型时明确降级，不假装完成 AI 分析。
- BYOK 和 Managed Cloud 均默认按项目 `denied`；授权时先执行最小化选择和可配置脱敏，并明确将哪些最小必要上下文发送给哪个 Provider。
- 云 AI 调用的 Prompt、原始输出与业务上下文只在本地版本化；控制面和普通日志不得保存业务正文、素材、记忆或原始 Prompt。
- 用户可以导出个人数据、项目和记忆；导出受限素材时给出版权提醒。
- MVP 不提供公开分享链接；后续分享必须基于显式对象和短期授权。

### 24.3 Local-first 事实源与可选控制面

- 桌面端本地数据库与本地文件是素材、项目、需求、决策、记忆、Prompt/输出版本、索引和图关系的唯一业务事实源；核心流程不依赖账号、Supabase 或网络在线。
- Supabase 仅可作为可选控制面，默认控制面区域暂定新加坡 `ap-southeast-1`；允许保存账号、订阅、模型目录和 Managed Cloud AI 用量，不得保存业务正文、素材、记忆、原始 Prompt 或可重建这些内容的向量。
- 新加坡是控制面区域，不是“用户数据区域”，更不是国际化本身。国际化仍取决于目标市场、语言、合规、支付和支持，拿一个 Region 给品牌贴金属于自欺欺人。
- 控制面不可用时，本地 Workspace 与本地模型继续工作；仅登录、订阅校验、模型目录刷新和 Managed Cloud AI 等依赖控制面的能力进入明确降级状态。

## 25. 数据隔离

### 25.1 隔离顺序

```text
本地 Workspace 所有权或会话校验
→ workspace_id
→ visibility / project_scope
→ client_scope
→ memory_scope / learning_policy
→ AI 路由 / 项目云授权 / 最小必要上下文
→ 检索、图谱扩展和 AI 上下文
```

### 25.2 硬性规则

- 所有业务查询先做 Workspace 过滤，再做全文、向量、图谱和缓存读取。
- Client 记忆默认不跨 Client；项目限定结论不得升级为个人通用记忆，除非用户显式确认。
- 改变项目隐私或作用域后，相关检索缓存和异步上下文立即失效。
- 团队模型预留不等于团队可读：个人记忆与团队记忆分开，团队知识不能覆盖个人认知。
- 删除请求在本地 T0 立即从默认界面、搜索、召回和 AI 上下文中排除，并使本地缓存、扩展队列和待执行 AI Job 失效；尚未物理清理完成不得成为继续调用的理由。
- T+7 前允许恢复软删除对象；T+8 起进入不可恢复的硬删除；设备正常运行的前提下，T+30 前必须清理 App 数据库、本地文件、全文/向量索引、图关系、缓存、扩展队列、派生数据和应用管理备份，并生成删除证明。
- 设备长期未运行时产品无法远程擦除本地副本：删除状态保持 `pending_device_execution`，在桌面端下次运行时继续；完成前不得伪造删除证明或宣称已物理清理。
- 删除证明至少包含请求标识、对象范围、T0 时间、硬删除完成时间、清理层级、离线待处理状态和失败重试结果。证明只覆盖 App 管理范围，不覆盖用户自己的 Time Machine、iCloud、系统快照、手工复制件或外部 Provider 留存。
- App 内只允许保留不含正文、不可反推内容的必要审计/抑制指纹；外部 Provider 的留存与删除按调用前披露的 Provider 条款执行，不能混进本地删除证明里冒充已清理。
- 项目与个人记忆是独立对象：删除项目不得隐式删除由该项目产生、且已被用户确认为个人长期记忆的内容；界面必须分别展示影响并让用户单独选择。
- 本地模型 Adapter、BYOK 与 Managed Cloud 必须保持可替换边界，不得形成单一供应商锁定。

## 26. 异常与降级

| 场景 | 用户反馈 | 系统处理 | 降级能力 |
|---|---|---|---|
| 桌面端未运行/插件无法交接 | 显示扩展本地已排队、已保存哪些内容 | 扩展持久队列、下次桌面端运行时幂等交接 | 继续采集，暂不进入桌面 Inbox |
| 重复点击/重复回调 | 返回同一任务状态 | 幂等键去重 | 不创建重复任务 |
| 页面/图片不可捕获 | 说明权限或页面限制 | 保存 URL、标题、笔记和可用预览 | 链接收藏 |
| 全页/局部截图失败 | 保留成功片段和选择范围 | 标记失败步骤可重试 | 当前视口或链接 |
| 批量导入部分失败 | 成功项不回滚，列出失败项 | 单项重试 | 手工重新选择 |
| AI 超时/不可用 | 原始内容可见，显示路由和分析延迟 | 对当前授权路由有限重试、熔断；不得擅自从本地切云或跨 Provider | 手工整理/本地关键词索引 |
| AI 空输出/非法 Schema | 明确“分析失败” | 拒绝写主表并记录 AIRun | 用户手工输入 |
| Embedding 失败 | 显示语义检索降级 | 后台重试 | 关键词/全文搜索 |
| 文档过长/格式非法 | 保留原文并指出具体限制 | 分块、OCR/解析失败记录 | 粘贴文本/手工拆解 |
| 用户中途退出 | 再次进入恢复进度 | 草稿和异步任务持久化 | 无需重做已完成步骤 |
| 并发编辑/版本冲突 | 展示版本差异 | 乐观锁、创建新版本 | 选择合并或保留两版 |
| 删除被引用对象 | 显示影响对象、7 天恢复窗口和最迟清理时间 | 本地 T0 抑制使用，T+7 前可恢复，T+8 起硬删除，设备运行条件下 T+30 前完成 | 保留不含正文的历史占位与删除状态 |
| 删除期间设备长期未运行 | 显示 `pending_device_execution` 和未覆盖范围 | 下次桌面端启动继续清理，完成前不出具完成证明 | 保持逻辑抑制，等待设备运行 |
| 上游来源失效 | 标记失效 | 保留已存快照和来源历史 | 用户补录来源 |
| 作用域/权限变化 | 结果即时刷新 | 缓存失效、取消越界 Job | 仅当前合法数据 |
| 记忆冲突 | 并排展示证据 | 状态改为 Challenged | 用户确认适用边界 |
| Managed Cloud 成本/额度超限 | 告知暂停的托管云能力 | 限流、批处理、低成本 Managed 模型 | 本地模型、BYOK、手工与基础检索 |

所有错误必须回答：发生了什么、哪些数据已安全保存、下一步能做什么。禁止只显示“操作失败”。

## 27. 非功能需求

### 27.1 性能

- 插件点击保存后 2 秒内反馈“桌面端已接收”或“扩展本地已排队”；AI 分析异步。
- 1,000 条个人素材规模下 Inbox/Library 首屏分页可用，不一次加载原图。
- 关键词搜索 P95 目标 < 1 秒；混合语义搜索 P95 目标 < 3 秒，超时降级关键词。
- 普通用户操作不等待视觉分析、Embedding、记忆整合或复盘完成。

### 27.2 可靠性与一致性

- 所有写操作幂等；异步任务至少一次投递时业务结果仍不重复。
- 原始资料、用户确认和 AI 派生结果版本化；关键状态有审计记录。
- 失败任务支持有限重试、死信/人工重放和明确状态。
- 本地数据库和应用管理备份必须可恢复、可校验并可纳入删除；用户自行启用的 Time Machine、iCloud、系统快照和手工复制不由 App 删除证明覆盖。

### 27.3 安全与合规

- 本地数据库、应用管理备份和敏感配置采用静态加密；BYOK 凭证只进入操作系统安全存储；云 AI 传输使用加密通道且不复用为控制面存储。
- 本地 Workspace/Client/Project/Memory Scope 在查询与 AI 上下文拼装前后均校验；控制面只对账号、订阅和用量元数据执行租户隔离。
- 本地运行日志默认不重复记录客户正文、图片内容和完整 Prompt；控制面与 Managed Cloud 普通日志禁止记录业务正文、素材、记忆或原始 Prompt。
- 导入内容执行类型、大小、恶意文件和脚本隔离校验。
- 隐私政策、数据处理说明、模型供应商说明和删除承诺在 Beta 前可见。

### 27.4 可用性与可访问性

- 加载、空、成功、失败、禁用和部分成功状态完整。
- 高风险删除有影响预览和确认；可恢复对象提供回收站。
- 键盘可操作、基础屏幕阅读语义和颜色对比达到桌面应用可访问性基线。
- 桌面 App 优先适配常见桌面窗口和窄窗；完整移动端与纯 Web 主产品后置。

### 27.5 可观测性与成本

- 本地关键链路有 trace、结构化日志、指标和告警；本地 AIRun 可关联业务对象但不重复正文。控制面 trace 只能使用不可还原的 Managed 调用标识，不得接收本地业务对象内容。
- 本地记录实际路由、模型、Prompt 版本、Token/图片、成本、延迟、失败、重试和用户采纳/拒绝；控制面只接收 Managed Cloud 的不含业务内容用量元数据。
- 监控采集成功率、Job 积压、检索降级、删除完成和越界拒绝。
- Managed Cloud 成本看板展示用户当月累计额、15 美元软阈值和 20 美元硬上限；阈值计算失败时采用保守限流。BYOK 与本地模型分开展示，不能错误计入 Managed Cloud 配额。

## 28. MVP 范围

### 28.1 P0 必须实现

1. **Local-first 桌面基座**：桌面端为主产品；本地数据库/文件为业务事实源；无账号、离线状态可使用核心流程；支持扩展交接、应用管理备份和本地删除证明。
2. **浏览器采集**：保存链接、当前视口、完整网页、框选局部、单张图片；记录来源、收藏原因/笔记、Inbox/项目/灵感板和处理状态；桌面端未运行时由扩展本地排队。
3. **素材系统**：图片、网页、截图、PDF/文档基础导入；Inbox、Library、AI 理解/标签、用户标签/笔记、Asset→Fragment、自然语言/向量/基础视觉相似检索、项目素材板、重复检测、来源与版权、价值生命周期。
4. **项目系统**：Client/Project、资料导入、需求拆解、模糊词/冲突/缺口、判断维度、个人素材/历史经验召回、正/反/边界案例、设计命题、决策与解释、反馈/结果、项目复盘。
5. **记忆系统**：用户明确偏好、项目/判断/失败记忆、候选、确认/编辑/删除、来源、作用域、简单衰减/冲突、个性化词典基础版、反向案例/同质提醒、新项目召回。
6. **知识图谱**：本地业务主表关系投影、节点/边溯源、局部需求证据图/素材影响图/决策图。
7. **AI 质量与安全**：Local/BYOK/Managed 路由分离、逐项目云授权、最小上下文、Schema、认知类型、本地 Prompt/模型/原始输出版本、基础 Evals、Managed Cloud AI 成本、采纳/拒绝、Memory Policy、项目隔离和删除验证。
8. **冷启动**：通用历史文件/图片/文档/链接清单导入；专用来源生成候选映射，不允许未经确认建立长期偏好；落实 500 文件/批、每 Workspace 1 个活跃批次 + 1 个排队批次、UTC 单日 2,000 文件上限。

### 28.2 MVP 验收闭环

必须用同一真实用户的两个项目证明：项目 A 的素材/决策/复盘产生一条用户确认记忆，项目 B 在合法作用域内召回并被用户查看或使用。只把 Memory 存进数据库不算完成。

### 28.3 范围纪律

- P0 中的功能可以按里程碑逐步上线，但不得通过修改 PRD 把基线锁定能力悄悄降为 P1。
- 若封测时间受限，优先减少格式/视图的精致程度和自动化深度，不切断纵向闭环、用户控制或隔离安全。

## 29. 后续版本范围

### 29.1 P1

- Figma Plugin/API：保存节点、Frame/Page/Component、版本、预览、灵感影响和回写引用。
- Eagle、Pinterest、Notion、浏览器书签等专用冷启动连接器。
- 全网研究与来源白名单、外部证据板和更强版权策略。
- 复杂素材类型（视频时间片、动效结构、字体许可）的深入理解。
- 高级决策说明模板、作品集过程导出和阶段复盘。
- 团队素材/方法/项目与个人/团队记忆分离，基础角色权限。
- 更完善的路径依赖、认知演化和成长轨迹。

### 29.2 P2

- 客户协作门户、评论与审批。
- 高级图谱路径分析和专题关系视图。
- 完整移动端与跨设备业务数据同步。
- 高级本地/专属模型管理和团队级 Provider 策略。
- 复杂多 Agent 研究与受控工作流。

### 29.3 明确非目标

- 自动生成完整最终设计稿并替用户决策。
- 为素材或设计师生成单一审美分。
- 以全局大型知识图谱作为主导航。
- 为绕过网站权限、登录或版权保护提供抓取能力。
- MVP 阶段引入微服务、独立图数据库或用户专属模型微调。

## 30. 成功指标

### 30.1 北极星指标

**月度证据化设计决策数**：用户在真实项目中主动保存，且至少绑定一条个人素材、历史经验或已确认记忆的设计决策数量。

### 30.2 激活指标

新用户 7 天内：

1. 成功收藏至少 3 条素材，且至少 1 条补充收藏原因。
2. 创建 1 个真实项目并导入需求。
3. 确认至少 1 个判断维度。
4. 将至少 1 条召回素材加入证据板。
5. 保存至少 1 条设计命题/决策。

### 30.3 过程与价值指标

- 素材：每周有效收藏、原因填写/后补、再次打开、进入项目、历史召回、加入 Board、影响最终设计。
- 判断：真实项目数、需求项确认/修改、模糊点/冲突发现、正反案例使用、命题进入最终方案、决策记录完成。
- 记忆：候选确认、后续调用、采纳、修改/否定、冲突/过期修正、删除完成。
- 长期：项目复盘率、新项目旧经验调用、个人词典增长、项目启动入口占比、用户主观“越来越理解我”。

### 30.4 风险指标

- 事实/推断错误标注率。
- 跨 Workspace/Client/Private Project 越界召回事件数：目标 0。
- 永久删除后仍被搜索、召回或进入 AI 上下文事件数：目标 0。
- 无来源/来源失效素材比例。
- AI 失败、超时、重试、人工介入和单位闭环成本。
- 记忆候选被拒绝/大改、反向提醒被判不相关的比例。

### 30.5 Beta Go/No-Go 假设门槛

首批 10–15 名品牌/网页视觉设计师中，若少于半数能在两周内完成一次完整闭环，或召回结果进入证据板比例持续低于 30%，暂停横向扩功能，优先修正采集上下文、需求建模和召回排序。门槛需由实际数据迭代。

## 31. 风险和应对方案

| 风险 | 影响 | 早期信号 | 应对 |
|---|---|---|---|
| 范围膨胀 | 多个半成品，纵向闭环不成立 | 每模块都有页面但跨模块无人完成 | 以两个项目闭环做唯一 P0 验收主线；按里程碑交付深度 |
| 收藏无上下文 | 召回仍是“看起来像” | 原因后补率低、命中理由弱 | 插件可跳过，Inbox/项目使用前二次提示；测试一句原因的价值 |
| 冷启动价值弱 | 新用户看不到个性化 | 首周无可用召回 | 通用批量导入、示例演示与最小手工选材，不伪造个性化 |
| 错误记忆 | 直接破坏信任 | 候选高拒绝/大改 | 重要推断候选确认、来源/范围可见、冲突并存、删除可验证 |
| 审美回音壁 | 推荐越来越同质 | 同类素材集中、反例使用低 | 反向案例、邻近探索、提醒强度和“为什么挑战” |
| 检索假相关 | 用户认为 AI 只会堆相似图 | 进入 Board 比例低 | 结合收藏原因、局部、项目关系、历史使用与用户反馈重排 |
| 客户隐私越界 | 信任/合规事故 | 跨客户命中、云载荷或控制面日志含正文 | 本地作用域前后校验、云载荷最小化、控制面禁存业务内容、安全回归零容忍 |
| 版权误解 | 用户错误商用或分享 | 许可 unknown 被当可商用 | 明确不作法律判断、来源/许可/失效、导出和分享提醒 |
| Managed Cloud AI 成本与延迟 | 单位经济性不可控 | Job 积压、每素材成本过高 | 异步、批处理、缓存、模型分层、15/20 美元预算和本地/BYOK 降级 |
| 控制面越界存储 | Local-first 信任崩塌 | Supabase 出现业务正文、素材、记忆或原始 Prompt | 控制面字段白名单、Payload 回归、日志扫描和零容忍发布门禁 |
| 数据模型过度抽象 | 开发慢、用户看不懂 | 为图谱而图谱 | 业务表为主、图谱投影；前端任务化局部呈现 |
| 双领域稀释 | 模板和召回都平庸 | 两类用户反馈相反且样本不足 | 首批只招募品牌/网页视觉设计师；UI/UX 仅做结构验证 |

## 32. 开发前决策状态

### 32.1 已锁定或明确延期

1. 正式产品名、品牌与域名明确延期决定；`DesignWan` 只作仓库工作名，命名不阻塞 MVP 开发。
2. 首批封测主领域锁定品牌/网页视觉设计师；具体招募标准和首个真实项目类型仍需细化。
3. 产品形态锁定为 Local-first 桌面主产品 + 浏览器采集伴侣；本地数据库/文件是业务事实源，核心流程可离线使用。
4. Supabase 仅为可选控制面，默认区域暂定新加坡 `ap-southeast-1`；只承载账号、订阅、模型目录和 Managed Cloud AI 用量，不是用户业务数据区域。
5. 模型策略锁定为本地模型 Adapter、BYOK Cloud、Managed Cloud 三路分离 + 受评测白名单；云 AI 必须逐项目授权并发送最小必要上下文。
6. 本地删除 SLA 锁定为 T0 不可见不可召回、T+7 前可恢复、T+8 起硬删除、设备运行条件下 T+30 前完成 App 管理范围清理并交付证明；设备离线时保持 `pending_device_execution`、下次运行继续。证明不覆盖 Time Machine/iCloud/系统快照、手工副本或外部 Provider 留存；项目删除不隐式删除个人记忆。
7. 冷启动容量锁定为 500 文件/批、每 Workspace 1 个活跃批次 + 1 个排队批次、UTC 单日 2,000 文件。
8. Beta Managed Cloud AI 成本锁定为每用户每月 15 美元软阈值、20 美元硬上限；本地模型与 BYOK 不计入。最终收费价格仍可另行实验，但不得突破该成本保护。

### 32.2 Beta 前仍需确认

1. 首批封测招募标准和用于验收的真实品牌/网页视觉项目类型。
2. 浏览器首发范围（Chrome/Edge）及 Firefox/Safari 顺序。
3. 基础冷启动导入格式细目、单文件大小上限和版权提示文案。
4. 个性化词典、反向提醒的默认开启状态和样本阈值。
5. Figma 链接的访问/预览边界；MVP 仅存链接还是允许桌面端抓取公开预览。
6. 首批本地模型目录、BYOK Provider 范围、Managed Cloud Provider 范围与各任务最小上下文模板。
7. 全网搜索进入 P1 时的来源白名单、版权和引用策略。

### 32.3 当前合理假设

- MVP 为个人 Local-first 桌面应用、单人本地 Workspace，Chromium 浏览器扩展只作采集伴侣；账号和控制面均为可选。
- 用户愿意导入真实项目的前提是业务数据不在云端持久化，云模型仅逐项目接收最小必要上下文，且 Provider 留存和删除边界可见。
- 通用主通道可服务品牌/视觉与 UI/UX，差异由领域模板和词典表达。
- 素材“为什么收藏”应可跳过，但必须有后补和项目使用前提示。
- AI 路由保持 Local/BYOK/Managed 可替换；云 AI 未授权时接受能力降级；用户选模不构成绕过项目授权、最小上下文和 Provider 条款的授权。
