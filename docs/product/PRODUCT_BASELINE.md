# DesignWan（仓库工作名）产品理解与决策基线

版本：v1.2  
状态：开发前产品决策已锁定  
关联文档：[完整 PRD](PRD.md)、[MVP 用户与业务流程](MVP_USER_FLOWS.md)、[术语表](GLOSSARY.md)

## 1. 产品理解

DesignWan 不是“AI 图片收藏夹”，也不是“会拆 Brief 的聊天机器人”。它要把设计师日常收集的视觉材料、真实项目里的需求与反馈、设计命题、取舍和最终结果连成一条长期可调用的认知链。

产品的核心对象不是图片，而是设计师面对某个具体任务时的判断：

```text
什么问题
→ 基于哪些事实、素材和经验
→ 用什么维度比较
→ 选择/放弃了什么
→ 接受了什么代价
→ 结果如何
→ 以后在什么条件下可复用或应避免
```

桌面端是主产品和本地业务事实源，负责素材、项目、记忆、检索与复盘；浏览器插件只是低摩擦采集伴侣，把内容交给桌面端。即使不登录账号、网络中断或控制面不可用，用户仍应能在本地完成核心闭环。

## 2. 核心价值

1. **素材复用价值**：从“按来源囤图”转为“按设计意图、局部价值和项目判断召回”。
2. **项目判断价值**：把模糊甲方语言拆成事实、推断、冲突、缺口、判断维度和证据。
3. **个人成长价值**：记录成功、失败、路径依赖和观点变化，让系统理解用户，但不替用户下结论。

北极星不是收藏量，而是“素材和历史经验实际参与了多少次可追溯设计决策”。

## 3. 最关键用户问题

首要问题不是“用户没有素材管理工具”，而是：

> 有经验的设计师无法低成本找回过去为什么收藏、为什么选择、为什么被否决，以及这些经验是否适用于眼前这个项目。

这个问题同时发生在三个时刻：

- 收藏时：保存快，但上下文容易丢。
- 项目启动时：按意图找不到旧素材，甲方语言又不可执行。
- 项目结束时：反馈和结果没有回写，经验再次流失。

## 4. 产品护城河

真正可能形成护城河的不是通用视觉识别、向量库或知识图谱组件，它们都可以买到或复制。可累积的差异是：

1. 用户亲自确认的“素材—需求—判断—决策—结果”关系数据。
2. 带客户、项目、领域和时间边界的个人设计词典。
3. 同时保存支持证据与反证、成功与失败、偏好与观点变化的记忆体系。
4. 围绕真实设计任务训练出来的召回反馈和 AI Evals 数据集。

这条护城河只有在用户持续把真实项目走到复盘和下一项目召回时才成立。若用户只收藏不复用，所谓“认知资产”就是一件穿了战略外套的素材仓库。

## 5. 与普通素材库的区别

| 普通素材库 | DesignWan |
|---|---|
| 保存文件、目录、标签 | 保存来源、收藏原因、局部、视觉特征和适用边界 |
| 按文件名/标签找图 | 按设计意图、判断维度、反向案例、历史使用和项目反馈召回 |
| 素材是终点 | 素材必须进入项目证据、影响命题/决策并留下结果 |
| 主要回答“我存过什么” | 回答“我为什么存、何时用、影响了什么、以后何时可用” |

## 6. 与普通 AI 对话工具的区别

| 普通 AI 对话 | DesignWan |
|---|---|
| 以当前上下文生成 | 在明确权限和作用域内调用用户自己的长期资产 |
| 推断和事实常混在同一段话 | 每条内容标注认知类型、来源、状态和置信度 |
| 记忆不透明或难以管理 | 记忆候选可确认、改写、限制、挑战、废弃和删除 |
| 给一个“看起来完整”的答案 | 展示证据、反证、信息缺口和需要用户判断的 Trade-off |
| 容易迎合旧偏好 | 反向记忆和边界案例主动防止审美回音壁 |

## 7. 最危险的产品风险

### 7.1 伪闭环

团队可能做出精致的收藏、搜索和 AI 拆解页面，却没有用户走到决策、复盘和下一项目召回。此时产品没有验证核心价值。

**应对**：以同一用户两个真实项目的跨项目召回作为 P0 验收，不接受单模块 Demo。

### 7.2 记忆信任崩塌

AI 一旦把单次行为推断为长期审美、把客户偏好当成用户偏好，或删除后仍在召回，用户不会把它当“小 Bug”，而会认为产品在偷偷塑造他。

**应对**：重要推断只进入候选；来源、范围、冲突和调用记录可见；永久删除立即阻止使用并验证派生数据清理。

### 7.3 认知负担反噬

如果每次收藏要求十几个字段、每个项目产生几十条记忆候选，用户会比整理 Eagle 更累。

**应对**：采集只保留一个主操作；原因可后补；候选按影响排序、批量处理并控制生成频率。

### 7.4 审美回音壁

个性化若只放大过去喜好，会让用户不断复用同一套路径。

**应对**：保存失败与反证；提供邻近探索和路径依赖提示；提醒强度由用户控制。

### 7.5 双领域稀释

品牌/视觉与 UI/UX 都覆盖，但若首批同时平均做两套模板，样本会被稀释、判断标准互相打架。

**应对**：产品主通道统一；首批封测已锁定为品牌/网页视觉设计师，UI/UX 仅用于验证领域扩展模型，不做平均投入。

## 8. 最危险的技术风险

### 8.1 作用域在检索后才过滤

向量搜索、图谱扩展、缓存或 Prompt 拼装若先查全库再由前端隐藏，会产生真实的数据泄露。

**应对**：Workspace/Client/Project/Memory Scope 必须进入候选查询条件，并在返回和 AI 上下文拼装前二次校验。

### 8.2 AI 派生数据污染主记录

非法 Schema、无来源推断或模型升级后的漂移若覆盖原始需求/用户确认，会让决策历史失真。

**应对**：原始输入、AI 原始输出、AI 结构化版本、用户确认版本分离；AI 失败不部分写业务主表。

### 8.3 删除只删本地主记录

正文删除后若本地文件、向量、图关系、索引、缓存、扩展队列、应用管理备份或旧 Job 仍在，就会“删了还能被 AI 说出来”。

**应对**：本地 Purge Job 覆盖 App 管理的全部派生层；接收删除后先加入全链路抑制；设备未运行时标记 `pending`，下次启动继续清理；删除回归是发布门禁。

### 8.4 异步链路不可追踪

图片分析、网页抽取、Embedding、需求拆解、记忆和复盘都异步，一旦没有幂等、状态和追踪，用户只会看到永远“处理中”。

**应对**：独立状态机、幂等键、有限重试、死信/人工重放、用户可读失败原因和 Job→业务对象追踪。

### 8.5 过早图数据库/微服务

此阶段将产品切成微服务、用 Neo4j 承担主交易，会把团队拖进分布式一致性和双写泥潭。

**应对**：桌面端模块化单体；本地数据库与本地文件为业务事实源，关系图只做本地业务对象投影，异步任务由本地 Worker 执行。Supabase 不承担业务主数据。

### 8.6 控制面偷渡业务数据

如果账号、订阅和 AI 计费控制面顺手保存业务正文、素材、记忆或原始 Prompt，所谓 Local-first 就只剩营销话术。

**应对**：Supabase 仅可作为可选控制面，保存账号、订阅、模型目录和 Managed Cloud AI 用量；不得持久化业务正文、素材、记忆或原始 Prompt。任何云 AI 都必须逐项目授权并只发送最小必要上下文。

## 9. 已识别的矛盾与校准结论

### 9.1 “低摩擦收藏”与“为什么收藏”的矛盾

- 风险：强制写原因会降低保存率；完全不写又失去核心上下文。
- 校准：插件中可跳过，进入 `needs_context`；Inbox 和第一次进入项目前再次提示补充；以“后补率与项目复用提升”验证价值。

### 9.2 “MVP 聚焦”与“必须完整纳入大量能力”的矛盾

- 风险：把所有能力都做成完整后台会失控；擅自后移又会切断愿景。
- 校准：P0 锁定完整纵向闭环和每个模块的最小可验收深度；减少格式、模板和自动化精度，不砍浏览器全采集、Fragment、复盘、记忆、隔离和 Evals 这些闭环节点。

### 9.3 “完整冷启动导入”与连接器成本的矛盾

- 风险：为每个平台维护连接器会吞掉 MVP。
- 校准：MVP 提供通用文件/图片/文档/链接清单/书签导出导入；专用 Eagle/Pinterest/Notion 连接器进入 P1；所有推断都待确认。

### 9.4 “持续学习”与“不建立隐藏人格档案”的矛盾

- 风险：行为个性化常在用户不知情下发生。
- 校准：行为事实可以自动记录，但重要长期归纳必须候选确认；Memory Center 展示来源、调用和删除控制。

### 9.5 “个人记忆”与“未来团队能力”的矛盾

- 风险：团队知识覆盖个人判断，或为了未来团队提前做复杂 RBAC。
- 校准：从第一天保留 owner/scope 字段和本地查询边界；MVP 不开放多人协作；个人与团队记忆是不同对象，不能互相覆盖。

### 9.6 “知识图谱完整建模”与“用户不想看蜘蛛网”的矛盾

- 风险：为展示图而建图，用户任务反而更难。
- 校准：图谱作为关系投影和检索/解释基础；前端只显示需求证据、素材影响、项目决策和认知演化等局部视图。

### 9.7 “同时服务两个领域”与“可验证 PMF”的矛盾

- 风险：通用化过早导致两边都不够用。
- 校准：统一主流程和领域协议；首批用品牌/网页视觉设计师验证频率与价值，再验证 UI/UX 扩展是否需要新实体，而不是两套产品。

## 10. 合理假设

以下不是已验证事实，开发和 Beta 应逐项验证：

1. 有经验设计师愿意在不超过约 20 秒的采集中补一句原因，或愿意在 Inbox 后补。
2. 收藏原因、局部和项目判断关系比通用视觉标签更能提高项目复用。
3. 用户愿意导入真实项目，前提是业务数据默认只在本地，云 AI 逐项目授权、发送范围可见且删除边界清楚。
4. 个人素材/经验召回可以先证明差异化；全网研究无需成为第一条闭环的必要条件。
5. 用户能接受少量高影响记忆候选，但不能接受每次操作都被要求“确认人格”。
6. 基础反向案例和路径提示能减少回音壁，而不会被视为系统越俎代庖。
7. 桌面端主产品 + Chromium 采集伴侣足以覆盖 MVP 主场景；完整移动端和纯 Web 主产品不是核心入口。

## 11. 范围分层

### 11.1 P0：闭环不成立就不能删

- 桌面主产品：本地数据库/文件事实源、离线核心流程、扩展交接、应用管理备份和本地删除闭环。
- 浏览器插件：链接、视口、全页、局部、单图、来源、原因、位置和状态。
- 素材：Inbox/Library、Asset/Fragment/VisualFeature、理解、混合检索、重复、来源/版权、项目板和使用生命周期。
- 项目：Client/Project、需求拆解、判断维度、正反边界证据、命题、决策、反馈/结果和复盘。
- 记忆：候选、确认/编辑/删除、来源、作用域、衰减、冲突、词典基础版、反向案例和新项目召回。
- 安全质量：项目/客户隔离、AI Schema/溯源/版本、基础 Evals、成本、采纳/拒绝和永久删除回归。
- AI 路由：本地模型 Adapter、BYOK Cloud 与 Managed Cloud 三条路由分离；云路由逐项目授权并做最小上下文传输。

### 11.2 P1：增强深度与外部连接

- Figma 深度集成、平台专用冷启动连接器、全网研究。
- 视频/动效/字体等高级理解与更复杂版权处理。
- 高级决策解释/作品集导出、团队基础能力和认知演化视图。

### 11.3 P2：规模化与复杂协作

- 客户门户、多人审批、完整移动端。
- 高级图谱查询、复杂多 Agent 工作流和跨设备业务数据同步。

### 11.4 明确不做

- 自动生成完整最终设计稿并替用户判断。
- 素材/作品/设计师单一审美评分。
- 绕过网站权限或版权保护。
- 以全局大型知识图谱为主导航。
- MVP 引入微服务、独立图数据库或用户专属模型微调。

## 12. MVP 价值验证

### 核心实验

让同一目标用户完成：

```text
项目 A 收藏和使用素材
→ 记录命题/决策和项目结果
→ 完成复盘
→ 确认一条记忆
→ 项目 B 合法召回该记忆
→ 用户采纳、挑战或明确标记不适用
```

### 成功信号

- 用户不是只保存，而是主动把召回结果放进证据板。
- 用户愿意修正需求拆解和记忆，而不是直接关闭 AI。
- 被召回的旧经验减少了找素材或重新解释的时间。
- 用户在第二个真实项目继续使用，而非只完成演示任务。

### 失败信号

- 原因填写/后补很低，导致召回只能靠表面视觉相似。
- 召回结果频繁被判不相关，或命中理由无法解释。
- 用户大量拒绝记忆候选，认为系统过度概括。
- 项目资料因隐私顾虑不愿导入。
- 用户完成收藏，却不创建真实项目或不做复盘。

## 13. 当前锁定决策

1. 正式产品名、品牌与域名延期决定；`DesignWan` 仅为仓库工作名，不作为最终对外命名，也不阻塞开发。
2. 收藏是高频入口，甲方需求/真实项目是价值入口。
3. 桌面端是主产品，浏览器插件是采集伴侣，二者均属于 MVP；Figma 深度集成后置。
4. 首批封测主领域锁定为品牌/网页视觉设计师；UI/UX 保留为后续领域扩展验证，不参与首批平均招募。
5. 个人用户优先；团队字段预留但不开放多人功能。
6. 重要记忆必须候选确认；AI 只能经 Memory Policy 写入。
7. 本地数据库与本地文件是素材、项目、记忆及其派生索引的事实源；图谱底层建模、桌面端局部呈现，不引入 Neo4j。
8. 商业价值按素材复用、证据化决策、复盘和记忆复用衡量，不按收藏总量。
9. Supabase 仅可作为可选控制面，默认控制面区域暂定新加坡 `ap-southeast-1`；只保存账号、订阅、模型目录和 Managed Cloud AI 用量，不得保存业务正文、素材、记忆或原始 Prompt。它不是用户业务数据区域，更不等于品牌国际化。
10. AI 路由明确分为本地模型 Adapter、BYOK Cloud 和 Managed Cloud；用户可在受评测白名单内设置默认/任务模型。任何云 AI 均需逐项目授权，明确提示将发送最小必要上下文，并受任务能力、Provider 隐私条款与预算策略约束。
11. 本地删除 SLA：T0 立即从界面、搜索、召回和 AI 上下文中不可见、不可调用；T+7 前可恢复；T+8 起进入硬删除；T+30 前清理 App 数据库、本地文件、索引、缓存、扩展队列和应用管理备份并生成删除证明。设备长期未运行时无法远程擦除，状态保持 `pending_device_execution` 并在下次运行继续；证明不覆盖 Time Machine、iCloud、系统快照或外部 Provider 留存。删除项目不隐式删除个人记忆。
12. 冷启动导入上限：单批最多 500 个文件；每个 Workspace 同时只允许 1 个活跃批次和 1 个排队批次；按 UTC 自然日最多接收 2,000 个文件。
13. Beta AI 成本配额仅约束 Managed Cloud AI：每用户每月 15 美元为软阈值、20 美元为硬上限；达到软阈值后提示并主动降级高成本任务，达到硬上限后暂停 Managed Cloud 高成本 AI。本地模型和 BYOK 成本不计入该配额，但仍需展示其独立状态与 Provider 责任边界。

## 14. 仍需产品决策

- 首批封测的具体招募标准和首个真实项目类型。
- 记忆候选每项目/每周的默认上限与批量确认体验。
- 个性化词典和反向提醒默认开启策略及最小证据阈值。
- 本地模型首批支持目录、BYOK Provider 范围及各云 Provider 的最小上下文规则。
- 冷启动格式细目、单文件大小限制和专用连接器的 P1 顺序。
- Beta 付费实验与最终定价；不得借定价未定绕过已锁定的 15/20 美元成本边界。
